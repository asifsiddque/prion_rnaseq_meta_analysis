Purpose of this document: Plain-language explanation of every script, every section, and every analysis — written so that anyone, including those new to bioinformatics, can understand what was done and why. This document is designed to make methodology writing straightforward.

How to Read This Document

The pipeline runs in order: 00 → 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08.

  • Scripts 00–03 are shell scripts (.sh) — they run on a Linux/Mac terminal (or MobaXterm on Windows). They handle downloading raw data and preparing it for analysis.
  • Scripts 04–08 are R notebooks (.ipynb) — they run in Google Colab. They perform all the statistical analysis, generate figures, and produce the final results.

Each script is divided into numbered Sections. This document explains every section in plain language, followed by a technical summary for methodology writing.

Script 00: 00_download_fastq.sh — Download Raw Sequencing Data

What this script does

RNA sequencing produces raw data files called FASTQ files. These files contain the actual DNA sequence reads from each sample, along with quality scores for each base. Before any analysis can happen, these files must be downloaded from the NCBI Sequence Read Archive (SRA) — the public database where researchers deposit their raw sequencing data.

How it works

The script reads a list of SRR accession numbers (e.g., SRR11684314) from a file called SRR_Acc_List.txt. Each SRR number identifies one sample's raw sequencing data. For each accession, it runs a tool called parallel-fastq-dump to download the FASTQ files.

Key parameters:

  • --threads 4: Uses 4 CPU cores to speed up the download
  • --split-files: For paired-end data, saves two files per sample (_1.fastq.gz and _2.fastq.gz — the forward and reverse reads)
  • --gzip: Compresses the output files to save disk space

Output: All FASTQ files are saved in the ../fastq/ directory, one folder per SRR accession.

Why this matters for methodology

This step establishes the raw data provenance. All 11 datasets were downloaded directly from NCBI SRA, ensuring reproducibility. The SRR accession numbers uniquely identify each sample and can be used by anyone to re-download the exact same data.

Script 01: 01_qc.sh — Quality Control of Raw Reads

What this script does

Before using sequencing data for analysis, you must check its quality. Poor-quality reads (low Phred scores, adapter contamination, rRNA contamination) can introduce noise and bias into downstream results. This script runs quality control (QC) on every FASTQ file.

How it works

Step 1 — FastQC: Runs FastQC on every .fastq.gz file. FastQC is the standard tool for RNA-seq QC. It generates an HTML report for each sample showing:

  • Per-base sequence quality: Phred quality scores across the read length. Scores ≥28 are acceptable (error rate <0.16%).
  • Adapter content: Whether sequencing adapters (short synthetic sequences added during library preparation) are present in the reads. High adapter content (>5%) means trimming is needed.
  • Duplicate rate: The fraction of reads that are exact duplicates. High duplication (>50%) can indicate PCR over-amplification.
  • Overrepresented sequences: Sequences that appear far more often than expected — often rRNA contamination.

Step 2 — MultiQC: Runs MultiQC to aggregate all individual FastQC reports into a single HTML summary. This makes it easy to compare QC metrics across all samples at once and identify outliers.

Key QC thresholds checked:

  • Per-base quality median ≥ 28 (Phred score)
  • Adapter content < 5%
  • Duplicate rate < 50%
  • No dominant overrepresented sequences (rRNA contamination)

Output:

  • ../outputs/qc/fastqc/ — individual FastQC reports
  • ../outputs/qc/multiqc_report.html — aggregated MultiQC report

Why this matters for methodology

QC is a mandatory step in any RNA-seq analysis. Samples failing QC thresholds would be flagged for exclusion or adapter trimming before proceeding. In this pipeline, all samples passed QC (no trimming step was needed), which is documented in the MultiQC report.

Script 02: 02_build_salmon_index.sh — Build Reference Indices for Quantification

What this script does

To count how many reads come from each gene, you need a reference index — a pre-processed version of the genome/transcriptome that allows the quantification tool (Salmon) to rapidly match reads to genes. This script builds two indices: one for mouse (used for 10 of 11 datasets) and one for human (used for GSE214373).

Background: What is a Salmon index?

Salmon is a tool that quantifies gene expression from RNA-seq data. Instead of aligning reads to the genome (which is slow), Salmon uses a technique called selective alignment — it rapidly matches reads to transcripts using a hash-based index. The index must be built once from the reference transcriptome before quantification can run.

How it works

Decoy-aware index (gentrome approach):
A standard Salmon index is built from just the transcriptome (cDNA sequences). However, some reads come from genomic regions that are not transcribed — these can map spuriously to transcripts and inflate counts. The decoy-aware approach adds the full genome as a "decoy" so Salmon can identify and discard these spurious mappings.

For each organism (mouse and human):

  1. Download reference sequences from Ensembl Release 111:

    • cDNA (protein-coding transcripts)
    • ncRNA (non-coding RNA transcripts — lncRNA, miRNA, etc.)
    • Genome (primary assembly — used as decoy only)

  2. Build decoy list: Extract chromosome names from the genome to tell Salmon which sequences are decoys.

  3. Combine cDNA + ncRNA into a gentrome: Concatenate the transcriptome and genome into a single file. This ensures that reads from non-coding genes are correctly quantified rather than mapping spuriously to protein-coding transcripts.

  4. Run salmon index with:

    • --keepDuplicates: Retains duplicate transcript sequences (important for multi-copy gene families)
    • --threads 8: Parallel processing
    • --gencode flag not used (Ensembl format)

Reference versions used:

  • Mouse: GRCm39 (Ensembl Release 111)
  • Human: GRCh38 (Ensembl Release 111)

Output:

  • ../inputs/mouse_salmon_index/ — used for all mouse datasets
  • ../inputs/human_salmon_index/ — used for GSE214373 only

Why this matters for methodology

The choice of reference genome version is critical for reproducibility. Using Ensembl Release 111 for both species ensures consistent gene annotation. The decoy-aware approach reduces false-positive mappings compared to a standard transcriptome-only index.

Script 03: 03_reads_quant.sh — Quantify Gene Expression with Salmon

What this script does

This is the core upstream step: it takes the raw FASTQ files and the Salmon indices, and produces gene expression counts — a number for each gene in each sample representing how many RNA molecules from that gene were detected.

Background: What is RNA-seq quantification?

In RNA-seq, cells' RNA is converted to DNA, fragmented, and sequenced. The resulting reads must be matched back to genes to count how much of each gene was expressed. Salmon does this by:

  1. Rapidly matching each read to the most likely transcript(s) using the index
  2. Using an expectation-maximisation (EM) algorithm to resolve reads that could come from multiple transcripts
  3. Correcting for technical biases (GC content, sequence composition)
  4. Outputting estimated counts and TPM (transcripts per million) values

How it works

The script reads sample_metadata.tsv — a tab-separated file with columns: SRR, GSE, LAYOUT (PAIRED/SINGLE), ORGANISM (mouse/human). For each sample:

  1. Select the correct index based on organism (mouse or human)

  2. Run Salmon with appropriate parameters:

    • --libType A: Automatic library type detection (Salmon figures out whether the library is stranded, unstranded, forward, or reverse)
    • --validateMappings: Enables selective alignment (more accurate than quasi-mapping)
    • --gcBias: Corrects for GC content bias (applied to all samples)
    • --seqBias: Corrects for sequence-specific bias (applied to paired-end only — single-end reads lack the fragment length distribution needed for this correction)
    • --threads 8: Parallel processing

  3. Resume-safe: If quant.sf already exists for a sample, it is skipped. This means the script can be safely re-run after interruption.

Output per sample: ../outputs/salmon_out/<GSE>/<SRR>/quant.sf
The quant.sf file contains one row per transcript with columns: Name, Length, EffectiveLength, TPM, NumReads.

Post-quantification check: The script prints mapping rates for all samples. Any sample with mapping rate <70% is flagged for investigation.

Why this matters for methodology

Salmon with --validateMappings and --gcBias is the current best practice for RNA-seq quantification. The use of a decoy-aware index and bias correction ensures accurate, reproducible count estimates. The quant.sf files are the direct input to all downstream R analyses.

Script 04: 04_build_coldata.ipynb — Build Sample Metadata Tables

Overview

Before running differential expression analysis, you need a coldata (column data) table for each study. This is a spreadsheet that describes each sample: which condition it belongs to (prion vs. control), what covariates it has (sex, age, time point, cell type, brain region), and where its quantification file is located. Script 04 builds these tables automatically by fetching metadata from GEO (Gene Expression Omnibus) and cross-referencing with the sample metadata file.

Section 0: Package Installation and Loading

Installs and loads the R packages needed:

  • GEOquery: Downloads metadata from GEO (the public database where RNA-seq studies are deposited)
  • readr, dplyr, stringr: Data manipulation tools
  • httr, jsonlite: For making API calls to NCBI to resolve SRX→SRR accession numbers

Section 1: Configuration

Sets up all file paths and defines the study registry — a named list mapping each GSE accession to its stratum (A, B, C, or D). This is the master list of all 11 studies.

Section 2: Load Sample Metadata

Reads sample_metadata.tsv — the manually curated file listing all SRR accessions, their parent GSE study, library layout (PAIRED/SINGLE), and organism. This file was created before running the pipeline and serves as the ground truth for which samples belong to which study.

Section 3: Helper Functions

Defines three key functions used throughout the script:

fetch_geo(gse_id): Downloads the full SOFT file for a GEO study. The SOFT file contains detailed per-sample metadata including experimental conditions, characteristics (age, sex, genotype, time point), and links to SRA accessions. Importantly, this uses GSEMatrix=FALSE to get the full SOFT file — the matrix format does not include per-sample characteristics.

parse_characteristics(gsm): Extracts the "key: value" pairs from a GEO sample's characteristics field. For example, a GEO sample might have characteristics like "genotype: wild-type" and "time point: 12 wpi" — this function parses those into a structured list.

extract_srx(gsm): Extracts the SRX accession number from a GEO sample's relation field. SRX numbers link GEO samples to their SRA sequencing data.

Section 4: Per-Study Coldata Construction

This is the main section. For each of the 11 studies, a dedicated code block:

  1. Fetches GEO metadata using fetch_geo()
  2. Parses sample characteristics (condition, time point, sex, cell type, brain region, etc.)
  3. Applies study-specific filters (e.g., for GSE124932, only wild-type animals are kept; for GSE149805, samples are stratified by cell type)
  4. Standardises column names across all studies (condition must always be "prion" or "control")
  5. Writes the coldata CSV to config/coldata/<GSE>_coldata.csv

Study-specific notes:

  • GSE149805 is a single-nucleus RNA-seq study with 4 cell types (CamKIIa neurons, Cx3Cr1 microglia, GFAP astrocytes, PV interneurons). The coldata includes a cell_type column so each cell type can be analysed separately.
  • GSE149805 has 10 samples intentionally excluded (they are from a different experimental arm not relevant to the prion vs. control comparison).
  • GSE124932 is filtered to wild-type animals only (excluding transgenic arms).
  • GSE202275 is filtered to prion+vehicle vs. control+vehicle arms only (excluding drug treatment arms).

Section 5: Validation and Summary

Checks that every expected SRR accession is accounted for in the coldata files. Prints a summary table showing, for each study: stratum, number of prion samples, number of control samples, and which covariates are present. Any unexpected missing samples trigger a warning.

Output files: config/coldata/<GSE>_coldata.csv for all 11 studies.

Script 05: 05_stream1_cns_meta_analysis.ipynb — Stream 1: CNS Meta-Analysis

Overview

This is the core discovery analysis. It takes the 5 Stratum A mouse brain studies and:

  1. Runs differential expression analysis (DESeq2) on each study separately
  2. Combines the results using meta-analysis to find genes consistently dysregulated across studies
  3. Defines the Mouse Conserved Prion Signature (MCPS) — the consensus gene set
  4. Tests whether the MCPS replicates in 4 independent held-out studies (Stratum D)
  5. Runs pathway enrichment analysis to understand the biological processes involved

Section 0: Package Installation and Loading

Installs and loads:

  • DESeq2: The standard tool for RNA-seq differential expression analysis
  • tximeta/tximport: Import Salmon quantification files into R
  • metafor: Run random-effects meta-analysis
  • fgsea: Gene Set Enrichment Analysis (GSEA)
  • msigdbr: Access the MSigDB gene set database
  • ggplot2, ggrepel, patchwork: Publication-quality figures
  • biomaRt, AnnotationDbi: Gene annotation (convert Ensembl IDs to gene symbols)

Section 1: Global Configuration

Defines all analysis parameters:

  • Significance thresholds: padj ≤ 0.05 (Benjamini-Hochberg FDR), |log2FoldChange| ≥ 0.5
  • I² threshold: 75% — genes with heterogeneity >75% are excluded from the MCPS
  • Minimum studies: 3 — a gene must appear in at least 3 of 5 studies to be included in meta-analysis
  • Study designs: The DESeq2 formula for each study (e.g., ~ time_point + condition for GSE144738)
  • LFC coefficient names: The name of the prion-vs-control contrast in each study's DESeq2 model

Section 2: Helper Functions

Defines the key functions used throughout the script:

load_coldata(gse): Reads the coldata CSV for a study, verifies required columns, rewrites file paths to point to the Salmon quant.sf files on Google Drive, and sets the control condition as the reference level for DESeq2.

import_with_tximeta(coldata, gse): Imports Salmon quantification files using tximeta. tximeta is preferred over tximport because it automatically links transcript-level quantifications to gene-level annotations using Ensembl metadata, and it preserves transcript length information needed for accurate count normalisation. Falls back to tximport + biomaRt if tximeta's API call fails (a common issue in Colab).

filter_low_counts(gse_obj, gse_id): Removes genes with very low counts. The threshold is: keep genes with ≥10 counts in at least half the samples. This step is important because genes with near-zero counts cannot be reliably tested and their inclusion would reduce statistical power after multiple testing correction.

detect_pca_outliers(gse_obj, gse_id): Performs Principal Component Analysis (PCA) on the variance-stabilised counts and flags samples that are statistical outliers (>3 standard deviations from the mean on PC1 or PC2). Outlier samples are removed before DESeq2 to prevent them from distorting the results.

run_deseq2(gse_obj, gse_id, design_formula, coef_name, out_dir): The core DESeq2 wrapper. Runs the full DESeq2 pipeline:

  1. Builds a DESeqDataSet with the specified design formula
  2. Runs DESeq2 (estimates size factors, dispersions, fits the negative binomial model)
  3. Applies apeglm LFC shrinkage — this is a Bayesian shrinkage method that pulls log2FoldChange estimates for low-count genes towards zero, reducing noise without introducing bias
  4. Extracts results for the prion-vs-control contrast
  5. Annotates results with gene symbols and Entrez IDs using biomaRt
  6. Saves the results CSV

annotate_mouse_genes(res_df): Adds gene symbol, Entrez ID, and Ensembl ID columns to a results data frame using biomaRt.

Section 3: Per-Study DESeq2 — Stratum A

Runs DESeq2 on each of the 5 Stratum A studies:

GSE149805 (N=186, 4 cell types): This study is handled specially because it contains 4 different cell types (neurons, microglia, astrocytes, interneurons). DESeq2 is run separately for each cell type, then the results are combined using a pseudobulk approach — for each gene, the log2FoldChange and standard error are averaged across cell types (weighted by the inverse of the variance). This produces a single combined result per gene that represents the average effect across cell types.

GSE198063 (N=36): Standard DESeq2 with design ~ condition. No covariates needed.

GSE144738 (N=60): Design ~ time_point + layout + condition. Time point (weeks post-infection) and sequencing layout (paired/single) are included as covariates to control for their effects.

GSE189527 (N=36): Design ~ time_point + condition.

GSE201249 (N=24): Design ~ brain_region + cell_type + condition. This study has samples from multiple brain regions and cell types, so both are included as covariates.

After each DESeq2 run, the results are saved as CSV files in results/deseq2/.

Section 4: Random-Effects Meta-Analysis (DerSimonian-Laird)

This is the statistical heart of Stream 1.

What is meta-analysis? Meta-analysis combines results from multiple independent studies to get a more reliable estimate of an effect. Instead of just asking "is gene X significant in study A?", meta-analysis asks "across all studies, what is the best estimate of how much gene X changes in prion disease?"

Why random-effects? A fixed-effects meta-analysis assumes the true effect size is identical across all studies. A random-effects meta-analysis (DerSimonian-Laird method) assumes that each study estimates a slightly different true effect (due to different prion strains, mouse strains, brain regions, time points), and models this between-study variability explicitly. Random-effects is more appropriate here because the studies are genuinely heterogeneous.

How it works:

  1. Build gene universe: Collect all genes that appear in at least 3 of the 5 studies with valid log2FoldChange and standard error estimates.

  2. For each gene: Run rma(yi = LFC_vector, sei = SE_vector, method = "DL") from the metafor package. This fits a random-effects model and returns:

    • meta_log2FC: The pooled (weighted average) log2FoldChange across studies
    • meta_SE: The standard error of the pooled estimate
    • meta_pvalue: The p-value for the null hypothesis that meta_log2FC = 0
    • Q_stat, Q_pvalue: Cochran's Q test for heterogeneity
    • I²: The percentage of total variance due to between-study heterogeneity (0% = all studies agree perfectly; 100% = studies are completely inconsistent)
    • tau²: The estimated between-study variance

  3. Apply BH-FDR correction: Adjust all p-values for multiple testing using the Benjamini-Hochberg method.

  4. Define MCPS: Genes meeting all three criteria:

    • meta_padj ≤ 0.05
    • |meta_log2FC| ≥ 0.5
    • I² ≤ 75% (not too heterogeneous)

Section 5: Held-Out Replication (Stratum D)

What is held-out replication? The 4 Stratum D studies were deliberately kept separate from the discovery analysis. After defining the MCPS from Stratum A, we test whether the same genes are also significantly dysregulated in the Stratum D studies. This is a form of independent validation — if the MCPS genes replicate in studies that were not used to discover them, it increases confidence that they represent a genuine prion disease signal rather than noise.

How it works:

  1. Run DESeq2 on each Stratum D study (same pipeline as Stratum A)
  2. For each MCPS gene, check whether it is: (a) present in the Stratum D study, (b) significant (padj ≤ 0.05), and (c) in the same direction (up or down) as in the MCPS

Leave-One-Out (LOO) sensitivity analysis: Additionally, the meta-analysis is re-run 5 times, each time leaving out one Stratum A study. This tests whether the MCPS is robust to the removal of any single study. If removing one study dramatically changes the MCPS, that study is a "dominant driver" and the MCPS is less reliable.

Key finding: Excluding GSE144738 reduces MCPS overlap to only 16.7% (1/6 genes), identifying GSE144738 as the dominant driver of the MCPS. All other LOO combinations retain ≥ 50% overlap (GSE149805: 100%, GSE198063: 100%, GSE189527: 50%, GSE201249: 83.3%).

Replication results (Stratum D held-out studies):

  • GSE202275: 100% replication (6/6 genes)
  • GSE124932: 50% replication (3/6 genes)
  • GSE90977: 0% replication (0/6 genes)
  • GSE207251: 0% replication (0/4 testable genes)
  • Mean replication rate across Stratum D: 37.5%

Critical limitation: The MCPS is substantially dependent on GSE144738. Removing this single study drops the signature from 6 to 1 gene. This must be stated explicitly in the manuscript as a sensitivity limitation.

Section 6: Pathway Enrichment Analysis

What is pathway enrichment? Individual genes are hard to interpret in isolation. Pathway enrichment analysis asks: are the dysregulated genes enriched in known biological pathways? If many genes from the "interferon signalling" pathway are upregulated, it suggests that interferon signalling is activated in prion disease.

Two complementary approaches are used:

Over-Representation Analysis (ORA) — per study:

  • Takes the list of significant DEGs from each study
  • Tests whether any biological pathway contains more DEGs than expected by chance (Fisher's exact test)
  • Run separately for upregulated and downregulated genes
  • Gene sets from: MSigDB Hallmark, KEGG, Reactome, GO Biological Process

Gene Set Enrichment Analysis (GSEA) — meta-analysis level:

  • Instead of using a binary DEG list, GSEA uses the full ranked gene list (all genes ranked by their meta-analysis z-score)
  • Tests whether genes in a pathway tend to cluster at the top (upregulated) or bottom (downregulated) of the ranked list
  • More powerful than ORA because it uses information from all genes, not just significant ones
  • Run using the fgsea package with 100,000 permutations

Consensus pathways: A pathway is called "consensus" if it is significant (padj ≤ 0.05) in at least 3 of the 5 Stratum A studies. This identifies pathways that are robustly enriched across studies, not just in one.

Result: 487 consensus pathways (enriched in ≥ 3/5 studies), 147 GSEA-significant gene sets. Top convergent pathways (significant in both ORA consensus AND GSEA): HALLMARK_ALLOGRAFT_REJECTION, REACTOME_INNATE_IMMUNE_SYSTEM, HALLMARK_INTERFERON_GAMMA_RESPONSE, REACTOME_NEUTROPHIL_DEGRANULATION, REACTOME_ADAPTIVE_IMMUNE_SYSTEM.

Script 06: 06_stream2_human_validation.ipynb — Stream 2: Human sCJD Validation

Overview

Stream 2 tests whether the mouse MCPS genes are also dysregulated in human sporadic Creutzfeldt-Jakob disease (sCJD) brain tissue. The dataset is GSE214373 (Dimitriadis et al. 2022 bioRxiv): 5 sCJD patients and 9 controls, frontal cortex post-mortem tissue.

Section 0: Libraries and Configuration

Loads all required packages and sets paths. Key configuration:

  • PADJ_THRESH = 0.05, LFC_THRESH = 0.5
  • STREAM1_DIR: Path to Stream 1 outputs (needed to load the MCPS)
  • ORTHOLOG_CACHE: Path to a cached biomaRt ortholog mapping (to avoid re-querying Ensembl every run)

Section 1: Load and Validate Coldata

Reads GSE214373_coldata.csv and validates it. Checks that:

  • Required columns are present (sample_id, files, condition, age, sex)
  • Age and sex are correctly formatted
  • Condition factor levels are set with "control" as reference

Also computes and reports the age confound: the correlation between age and condition. In this dataset, sCJD patients are ~12 years younger than controls (mean age: 71.6 vs. 83.3 years), creating a significant confound (r = −0.60, p = 0.024). This is a critical limitation that must be addressed in the analysis design.

Section 2: Load Salmon Quantifications

Imports the human Salmon quantification files using tximeta. The human Salmon index (GRCh38, Ensembl r111) is used. The same import pipeline as Stream 1 is applied.

Section 3: Sample-Level QC

Runs PCA on variance-stabilised counts to check for outlier samples. Generates:

  • Fig 1a: PCA plot coloured by condition and sex
  • Fig 1b: Sample distance heatmap

Also generates Fig 2: Age confound visualisation (scatter plot of age vs. condition, with the Pearson correlation and p-value annotated).

Section 4: Primary DESeq2 Model — ~ age + sex + condition

Why include age as a covariate? Because age is correlated with condition (r = −0.60), not including it would confound the disease signal with age-related transcriptional changes. By including age as a continuous covariate, DESeq2 estimates the effect of condition (prion vs. control) while statistically controlling for age differences.

How it works:

  1. Build DESeqDataSet with design ~ age + sex + condition
  2. Pre-filter: keep genes with ≥10 counts in at least 5 samples (= min(n_prion, n_control))
  3. Check design matrix rank (must be full rank — if not, fall back to ~ age + condition)
  4. Run DESeq2 with Wald test
  5. Apply apeglm LFC shrinkage for the condition_prion_vs_control coefficient
  6. Annotate results with human gene symbols

Result: 118 DEGs (92 upregulated, 26 downregulated in sCJD).

Section 5: Sensitivity Analysis — ~ sex + condition (age omitted)

Why run a sensitivity analysis? To quantify how much of the signal is driven by the age confound. If the primary model (with age) and the sensitivity model (without age) give very similar results, the age confound is not a major problem. If they give very different results, many DEGs in the sensitivity model are likely age-driven false positives.

Result: 1,572 DEGs without age adjustment. Jaccard similarity between the two models = 0.071 (only 7% overlap). This means 93% of the sensitivity-model DEGs are age-confounded. The primary model's 118 DEGs are the defensible set.

Fig 3: Venn diagram / overlap plot showing the relationship between primary and sensitivity model DEGs.

Section 6: Human → Mouse Ortholog Mapping

Why is this needed? The MCPS was defined in mouse. To test whether MCPS genes are dysregulated in human sCJD, we need to find the human equivalents (orthologs) of the mouse MCPS genes.

How it works:

  1. Query Ensembl BioMart to get all human-mouse ortholog pairs
  2. Filter to 1:1 orthologs (one human gene maps to exactly one mouse gene) — these are the most reliable mappings
  3. Filter by percent identity ≥ 60% (ensures the proteins are functionally similar)
  4. Join the ortholog map with the human DESeq2 results

Result: 13,520 human-mouse 1:1 ortholog pairs. Of the 6 MCPS genes, only 1 (Parp14 → PARP14) has a 1:1 ortholog that is present and testable in the human dataset.

Expanded ortholog analysis (added in v2): For MCPS genes without 1:1 orthologs, a targeted search is performed:

  • Tasl → SLC15A4 (1:1, found in dataset)
  • Igsf6 → IGSF6 (1:1, found in dataset)
  • Fcgr4 → FCGR3A (best functional paralog — Fc receptor family)
  • Il1a → IL1A (1:1, but NOT found in dataset — filtered for low expression)
  • Iigp1 → no human ortholog (rodent-specific gene)

Section 7: MCPS Concordance Analysis

What is concordance? A gene is "concordant" if it changes in the same direction in human sCJD as in the mouse MCPS. For example, if Parp14 is upregulated in mouse CNS prion disease (MCPS LFC = +0.62) and PARP14 is also upregulated in human sCJD (human LFC = +0.19), they are concordant.

How it works:

  1. Join the MCPS with the human ortholog results
  2. For each testable MCPS gene, check: (a) is it significant in human? (b) is the direction the same?
  3. Run a binomial test: if genes were randomly up or down, we'd expect 50% concordance by chance. The binomial test asks whether the observed concordance is significantly better than chance.
  4. Compute Pearson correlation between mouse meta-LFC and human LFC for testable genes.

Result: Only PARP14 is testable (1:1 ortholog present and expressed above threshold). It shows directional concordance (both upregulated: mouse meta-LFC = +0.62, human LFC = +0.19) but is not significant in human (padj = 0.49). The human dataset is underpowered to detect this effect size (minimum detectable LFC at 80% power = 1.50 at median dispersion).

Saves: GSE214373_MCPS_concordance.csv and MCPS_human_concordance.csv

Section 8: GSEA — MCPS as a Gene Set on Human DEG Ranking

What is this testing? Instead of looking at individual genes, this asks: as a group, do the MCPS genes tend to be upregulated in human sCJD? The MCPS genes are treated as a gene set, and GSEA tests whether they are enriched at the top of the human DEG ranking.

How it works:

  1. Rank all human genes by their signed -log10(p-value) × sign(LFC) — this puts the most significantly upregulated genes at the top and most significantly downregulated at the bottom
  2. Run fgsea with the MCPS as the gene set
  3. The Normalised Enrichment Score (NES) measures how much the MCPS genes cluster at the top vs. being randomly distributed

Result: GSEA returns 0 results. After ortholog mapping, fewer than 3 MCPS genes have valid rank statistics in the human DEG list, falling below fgsea's minimum gene set size. An empty CSV (GSE214373_GSEA_MCPS.csv) is written with the correct column headers. This means the GSEA leading-edge criterion for evidence tiers (Tier 1–3) cannot be applied. The primary human validation evidence is the pathway-level GSE124571 analysis (see Script 08, Section 9).

Section 9: Power Analysis

What is power analysis? Power is the probability of detecting a true effect. With only 5 sCJD patients and 9 controls, the human dataset has limited statistical power. The power analysis quantifies: what is the minimum log2FoldChange that this dataset could reliably detect?

How it works:

  1. Estimate the dispersion (biological variability) of genes in the real dataset at three percentiles: 10th (low variability genes), 50th (median), 90th (high variability genes)
  2. For each true LFC value (0 to 3, in steps of 0.25), simulate 1,000 datasets with that effect size and the estimated dispersion
  3. Run DESeq2 on each simulated dataset and record whether the gene is detected as significant
  4. Power = fraction of simulations where the gene is detected

Result: At median dispersion, 80% power requires LFC ≥ 1.50. The observed MCPS gene LFCs in human are all <0.20 — well below the detection threshold. This confirms that the human dataset is underpowered to detect the effect sizes seen in mouse, not that the genes are truly not dysregulated.

Script 07: 07_stream3_peripheral_analysis_v2.ipynb — Stream 3: Peripheral Longitudinal Analysis

Overview

Section 5: Arm A — Longitudinal LRT (Likelihood Ratio Test)

What is the LRT testing? The LRT tests whether a gene's expression trajectory over time is different between prion-infected and control mice. Specifically, it tests for a condition × time interaction — genes where the rate of change over time differs between groups.

Why use LRT instead of a simple comparison? A simple comparison (prion vs. control at one time point) would miss genes that change gradually over time. The LRT captures the full longitudinal trajectory.

How it works:

  1. For each tissue, build a DESeqDataSet with design ~ condition + wpi + condition:wpi (where wpi = weeks post-infection as a continuous variable)
  2. Important: The terminal time point is excluded from Arm A because its exact wpi is unknown (it varies between animals). Only the 7 defined time points (4, 8, 12, 14, 16, 18, 20 wpi) are used.
  3. Run DESeq2 with the Likelihood Ratio Test — this compares the full model (with interaction) to a reduced model (without interaction). A significant result means the interaction term is needed, i.e., the trajectories diverge.
  4. Apply BH-FDR correction.

Result:

  • Whole blood: 129 significant genes (diverging trajectories)
  • Spleen: 0 significant genes
  • Skeletal muscle: 0 significant genes

The 0 results for spleen and muscle are not a failure — they reflect the biology. The spleen undergoes massive changes at the terminal stage (erythroid collapse) but not a gradual divergence over time. The LRT is specifically designed to detect gradual divergence.

Section 6: Arm B — Terminal Wald Test

What is the terminal Wald test? This tests for differential expression at the terminal stage (the final time point, when mice are moribund). Unlike Arm A, this is a simple two-group comparison (prion vs. control) at one time point.

Why a separate analysis for the terminal stage? The terminal time point is the most biologically relevant — it represents end-stage disease. It is also the time point most comparable to the human post-mortem brain tissue in Stream 2.

How it works:

  1. Subset each tissue dataset to terminal-stage samples only
  2. Run DESeq2 with design ~ condition (or ~ cohort + condition for skeletal muscle, which has two cohorts)
  3. Apply apeglm LFC shrinkage
  4. Threshold: padj ≤ 0.05, |LFC| ≥ 0.5

Result:

  • Whole blood: 14 DEGs (7 up, 7 down)
  • Spleen: 1,627 DEGs (468 up, 1,159 down)
  • Skeletal muscle: 293 DEGs (138 up, 155 down)

Notable finding: The top spleen terminal DEGs are erythroid genes (Ank1, Kel, Rhd, Hemgn, Ermap, Car2, Slc4a1, Pklr, Epb42, Spta1) — all strongly downregulated (LFC −5 to −8). This reflects a collapse of splenic erythropoiesis at terminal prion disease, consistent with known prion-associated anaemia.

Section 7: Annotation

Annotates all DESeq2 results (LRT and terminal) with gene symbols, biotype (protein-coding, lncRNA, etc.), and Ensembl IDs using biomaRt. This step is run after DESeq2 to avoid slowing down the model fitting.

Section 8 & 9: Arm C — MCPS Concordance and First Detection

Arm C — MCPS concordance (terminal): For each tissue, checks whether the 6 MCPS genes are:

  1. Present in the terminal DESeq2 results
  2. Significant (padj ≤ 0.05)
  3. In the same direction as the CNS MCPS (concordant)

Runs a binomial test for each tissue: if concordance were random (50%), what is the probability of observing the actual concordance by chance?

Also computes Pearson correlation between mouse meta-LFC (from Stream 1) and peripheral terminal LFC for testable MCPS genes.

Result:

  • Whole blood: 2/6 concordant (33.3%), binom_p = 0.81 (not significant)
  • Spleen: 2/6 concordant (33.3%), binom_p = 0.89 (not significant)
  • Skeletal muscle: 1/6 concordant (16.7%), binom_p = 0.88 (not significant)

This is a genuine negative result. No MCPS gene shows statistically significant concordant dysregulation in any peripheral tissue at the terminal stage. Direction concordance is no better than chance in all three tissues.

Critical finding — direction discordance: The genes first detected in peripheral tissues (Igsf6 at 14 wpi in blood, Fcgr4 at 16 wpi in spleen) are downregulated in the periphery, while they are upregulated in the CNS. This direction reversal is a genuine biological signal, not a pipeline error. It may reflect tissue-specific immune regulation (e.g., peripheral immune exhaustion vs. CNS microglial activation).

First detection analysis: For each tissue, runs per-timepoint Wald tests (prion vs. control at each individual time point). For each MCPS gene, identifies the earliest time point at which it is significantly dysregulated (padj ≤ 0.05). This gives the "first detection" time point — the earliest peripheral signal of prion disease for each gene.

Result:

  • Fcgr4 first detected in spleen at 16 wpi (LFC = −0.94, downregulated)
  • No MCPS genes detected in skeletal muscle at any pre-terminal time point
